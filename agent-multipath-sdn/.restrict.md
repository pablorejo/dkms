# Restricciones (INMUTABLE durante la ejecución)

> El agente DEBE releer este archivo en cada iteración. Si un objetivo
> en `.objetives.md` choca con una restricción, gana la restricción —
> el agente anota el conflicto en `.memory.md` y trabaja en otro
> objetivo hasta que el usuario resuelva.

## R-001 — Dependencias

- NO introducir solvers LP externos: `good_lp`, `clarabel`,
  `scipy.optimize`, `OR-tools`, `cvxpy`, `coin_or`, ni sus bindings.
- NO añadir crates pesados (>1 MB compilado) sin justificación
  explícita en `.memory.md`. Mantener el solver en pure-Rust water-
  filling greedy.
- Si necesitas álgebra, las opciones permitidas son las ya presentes en
  el workspace: `petgraph`, `ndarray`, `nalgebra`. Verifica en
  `Cargo.toml` antes de añadir.

## R-002 — QKC y wire protocol

- NO modificar el wire protocol de QKC (`common/src/ipc/binary_tcp.rs`).
- NO añadir endpoints HTTP a QKC.
- El campo `Frame.header_qkc_mp` puede leerse, pero idealmente NO se
  toca su semántica.

## R-003 — DKMS intacto

- NO tocar `dkms/src/` salvo para tests de integración que validan el
  cambio multipath end-to-end (que sería excepcional y solo si lo pide
  un objetivo explícito en `.objetives.md`).
- NO cambiar la API HTTP DKMS↔SAE (ETSI 014/020).

## R-004 — Semántica del fair sharing

- NO cambiar la semántica de max-min fairness por max-throughput o
  proporcional-fair. Mantener weighted max-min.
- NO romper las dos fases HIGH/LOW del solver. Pueden añadirse
  sub-fases si la decisión OBJ-002 lo justifica, pero la separación
  HIGH={Priority, Important, Quickly} / LOW={Relax, BestEffort} se
  queda.
- Pesos decade-spaced (10000/1000/100/10/1) se mantienen salvo
  modificación documentada en `.architecture.md`.

## R-005 — Rendimiento

- Tiempo de solver < 200 ms en topología mediana (N=20, ~30 edges, K=3
  paths). Medir con `cargo bench -p sdn` o instrumentación ad-hoc; si
  excede, optimizar antes del siguiente OBJ.
- No reintroducir alocaciones por iteración del water-filling en el
  hot path (reusar buffers donde sea trivial).

## R-006 — Tests verde

- `cargo test --workspace` debe quedar verde tras cada iteración.
- `cargo clippy --workspace -- -D warnings` debe quedar verde tras
  cada iteración.
- `make topo-cli-test` debe quedar verde tras cada iteración que toque
  `tests/cli/`.
- Si un cambio rompe tests, NO avanzar al siguiente objetivo hasta
  arreglarlo. La próxima iteración prioriza el fix.

## R-007 — Topología por defecto = EKS

- Cluster `dkms1` en `eu-north-1`. Contexto kubectl confirmado.
- Port-forwards: `kubectl -n dkms-main-ns port-forward svc/authz
  18081:8081` y `svc/orchestator 18080:8080`.
- Credenciales: `config_user` / `config_password` (uid=3 confirmado).
- NO ejecutar saturation tests en local sin cgroup memory-bounded. EKS
  es la única ruta segura por defecto (ver CLAUDE.md sección
  "Saturation / load tests").
- Excepción: tests UNIT (cargo test) corren en local sin riesgo, son
  micro-tests, no soak.

## R-008 — node_id offset

- Cota: `node_id ≤ 155` por bug ck_host_ipv4.
- Antes de lanzar sims grandes, consultar `kme.local_qkc_id` ya
  ocupados en BD y elegir offset que no colisione. Patrón
  documentado en
  `.claude/projects/-home-pablopio-Documentos-trabajo-atlantic-dkms-rust/memory/project_dkms_topo_safe_offset.md`.
- Si el offset elegido colisiona, ABORTAR el lanzamiento, anotar en
  `.memory.md` y reprogramar para la próxima iteración.

## R-009 — Cambios estructurales

- Cualquier cambio estructural (nuevo módulo, nuevo trait público,
  nueva dep, nuevo RPC, nuevo flujo inter-componente, nuevo evento
  pub/sub) DEBE actualizar `.architecture.md` con un entry en
  "Historial de cambios arquitectónicos" indicando fecha + iter.
- El agente NO puede prometer "luego lo documento". El doc se
  actualiza en la MISMA iteración que el código.

## R-010 — Reversibilidad

- Commits pequeños, atómicos, con `git revert` viable.
- NO `git push --force`.
- NO `git reset --hard` sin haber guardado el estado actual como rama
  backup (`git branch backup/iterNNN-pre-reset HEAD`).
- NO operaciones destructivas (`rm -rf`, `git clean -fd`, etc.) sin
  log previo en `.memory.md` del estado que se borra y por qué.
- Pre-commit hooks: si fallan, NO hacer `--no-verify`. Arreglar y
  recommit como NUEVO commit (no `--amend`).

## R-011 — Memoria del agente

- Append-only a `.memory.md`. NO truncar ni reescribir entradas
  pasadas; corregirlas con una nueva entrada que las invalide
  explícitamente.
- `.results.md` SÍ se reescribe completo cada iteración (tabla
  resumen).
- `.objetives.md` solo lo modifica el USUARIO o el agente para
  cambiar `[ ]` → `[x]`. NO añadir/quitar objetivos automáticamente;
  si el agente cree que falta uno, lo anota en `.memory.md` como
  propuesta y deja al usuario decidir.
