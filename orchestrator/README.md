# Kubernetes Orchestration Module

## Purpose

This module contains the orchestration logic and HTTP API used to create, run,
stop, update, and delete simulations on Kubernetes.

## What it contains

- `api_orchestator.py`: FastAPI management API
- `orchestator.py`: orchestration service and business logic
- `pods.py`: Kubernetes resource builders
- `seed_db_from_configs.py`: utility for seeding persistence from config files

Key symbols:

- `Orchestator` in [`orchestator.py`](orchestator.py)
- FastAPI app in [`api_orchestator.py`](api_orchestator.py)

## Runtime behavior

The module exposes grouped endpoints under `/orch` for:

- health checks
- simulation CRUD
- simulation run and stop operations
- web-facing simulation editing and run history
- SAE administration and certificate lifecycle

For the concrete route contract, see
[readme.api.orchestator.md](readme.api.orchestator.md).

## Key inputs

Important environment variables:

- `ORCHESTATOR_HOST`, `ORCHESTATOR_PORT`
- `ORCH_KME_MATERIAL_DIR`
- `DB_URL`, `PERSISTENCE_BACKEND`
- `SDN_IMAGE`, `DKMS_IMAGE`, `QUDITTO_IMAGE`
- `K8S_IMAGE_PULL_SECRET`, `K8S_IMAGE_PULL_POLICY`
- `QUDITTO_RATE_R0`, `QUDITTO_RATE_ALPHA` (defaults for the per-link
  rate model used to generate the simple_quditto config)
- `QUDITTO_REQUEST_TIMEOUT_PER_KEY_SECONDS`, `QUDITTO_DEC_KEYS_TIMEOUT_SECONDS`
- `QUDITTO_DEC_KEYS_TIMEOUT_MARGIN_SECONDS`
- `KME_DEC_KEYS_RETRY_WINDOW_SECONDS`, `QKC_DEC_KEYS_RETRY_WINDOW_SECONDS`
- `K8S_OBSERVABILITY_ENABLED`

`K8S_OBSERVABILITY_ENABLED` is enabled by default, so Prometheus, Loki,
Grafana, and promtail sidecars are deployed unless you explicitly disable them
with `K8S_OBSERVABILITY_ENABLED=false`.

Many more deployment-time settings are defined in `pods.py`.

When a simulation is started through `Orchestator.run_simulation(...)`, the SDN
runtime deployment now also receives:

- `SDN_ENABLE_DKMS_METRICS_LINK_STATE_SYNC=true`
- `SDN_ENABLE_QKC_LINK_CAPACITY_SYNC=true`

This makes the deployed SDN consume runtime DKMS `/metrics` and QKC
`/link_capacity` signals by default, instead of requiring an extra manual env
override for each simulation.

The runtime topology injected into SDN is also canonicalized to the
in-cluster service names actually reachable from the SDN pod. DKMS, ORR, QKC,
and local KME endpoints therefore use names such as `dkms-13` instead of
legacy `127.0.0.x` payloads, which keeps SDN periodic runtime syncs reachable
in Kubernetes.

For DKMS pods with the bundled Quditto sidecar:

- per-link QKD rate-model parameters (`distance`, `rate_r0`, `rate_alpha`) are
  rendered into the generated `config.yaml` mounted into the sidecar
- the global defaults `QUDITTO_RATE_R0` and `QUDITTO_RATE_ALPHA` are also
  injected as container env vars, so legacy/fallback simulator paths use the
  same deployment-level defaults instead of hard-coded simulator values
- the main `dkms` container now also receives `QKC_ENABLE_TOKEN_BUCKET=true` by
  default, so the QKC `/link_capacity` endpoint starts exposing runtime
  capacity estimates in Kubernetes even when the injected runtime topology does
  not include an explicit per-link `token_bucket` stanza
- for the faster Quditto runtime used by current deployments, the generated
  env defaults also keep `QUDITTO_DEC_KEYS_TIMEOUT_SECONDS`,
  `QUDITTO_DEC_KEYS_TIMEOUT_MARGIN_SECONDS`,
  `KME_DEC_KEYS_RETRY_WINDOW_SECONDS`, and
  `QKC_DEC_KEYS_RETRY_WINDOW_SECONDS` bounded to `15` seconds unless you
  override them explicitly, so decrypt-side relay retries do not inherit the
  older long-running per-attempt retry budgets; the default Quditto timeout
  margin is `2.5s`
- even with that legacy `15s` budget, the outer relay wrapper in
  `QKC/server.py` now derives a larger default total retry window when
  `QKC_SERVER_DECRYPT_RETRY_WINDOW_SECONDS` is not set explicitly; Kubernetes
  deployments generated by this repository also inject an explicit
  `QKC_SERVER_DECRYPT_RETRY_WINDOW_SECONDS=60` by default, which leaves room
  for several full QuDitto `dec_keys` waits before surfacing a relay failure
